# Method and interpretation

The model follows each synthetic person-topic-cycle request through detection, compatible-topic grouping, resource booking, theory, required individual practice and documentation. It preserves original waiting ages and deadlines. A feasible small group or individual fallback can start at the SOLL deadline; insufficient capacity remains an explicit breach. The IST urgency review is a separate rule. Completing a document does not create training competence.

One canonical Python engine composes policies. Scheduling respects trainer qualifications, rooms, participant calendars, theory prerequisites and working-time constraints. The scheduler uses deadline-ordered provisional plans; it is not a global optimizer. Independent random streams and stable request identities support paired comparisons on the same demand.

Treat the assets as frozen projections; the included public engine and local dashboard support new experiments but do not promise to rebuild every historical chart.

## Assumptions and measures

The annual example assumes 15 groups of 20 plus 50 individual cases, distributed across a synthetic pool of 45 people. This is 350 training needs, not 350 different people or a measured annual arrival rate. One P&Q theory role and one practice coach each have two bookable eight-hour days per week. Individual practice lasts 180 minutes in the baseline. These operating choices need real-world validation.

A full completion means that the required training phases finished. First start, full training and completed documentation are distinct metrics. A case can finish theory while remaining in the practice queue. The 14-day common comparison target is an analytical measure and does not impose an IST timeout.

The extra-coach branch adds a second qualified practice coach and place to combined SOLL; it does not stack on the LMS branch. Full additional salary, hiring and qualification are outside the reported cost boundary. Cost differences value consumed work and LMS resources, not observed cash savings or equal-output savings.

The displayed 50-fixture completion gain is 35.76 cases, with a pointwise approximate 95% model interval of 28.80–42.72. This describes random model variation under fixed assumptions, not uncertainty about actual operating conditions. Five-fixture sensitivity results have no confidence intervals. Their influence score depends on tested ranges and equal weights across metrics; it measures change, not improvement.

## Engineering checks

Run outputs record resolved inputs, seed maps, demand, events, sessions, costs, diagnostics and source/code hashes. Checks cover phase order, resource/person overlaps, queue ages, duplicate demand, partial work, cost reconciliation and immutable output directories. Public run manifests record a relative engine location rather than the user's absolute filesystem path.

Source-status labels distinguish verified source content, reported estimates, derived values and prototype assumptions. Source verification does not imply empirical measurement. The public manifest verifies the included sanitized inputs, not the excluded original private documents.
